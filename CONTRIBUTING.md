# Contributing to Sentinel Vault / Contribuindo com o Sentinel Vault

---

## 🇺🇸 English Guidelines

Thank you for your interest in the Sentinel Vault ecosystem! To ensure the security, architectural integrity, and governance of the Core Engine, all community interactions must comply with the guidelines below.

### 🤝 How Can You Participate?
As Sentinel Vault operates under a proprietary source-available license, contributions do not grant automatic code merging, but rather focus on the intellectual enrichment of the ecosystem:

* **Suggestions, Critiques, and Architectural Dialogues:** We encourage deep discussions regarding JVM performance optimizations, new cryptographic standards, or advanced DevSecOps techniques. You can open discussions and debate specific concepts through the repository's communication tools.
* **Bug and Vulnerability Reporting (Issues):** If you discover any security flaws (such as authentication bypasses or vulnerabilities in Actuator endpoints), open an Issue detailing the technical scenario, observed behavior, and step-by-step reproduction guide.
* **Pull Requests and Code Submission:** If you wish to submit a code improvement, be aware that by sending the Pull Request, you agree to assign the usage rights of the submitted code for incorporation into the main Core Engine, without intellectual property claims over the final product. Total and exclusive control remains in the hands of the creator, Lucas Silva de Deus. All submitted code must pass the automated local test suite (`mvn test`).

## 🇧🇷 Diretrizes em Português

Obrigado por se interessar em colaborar com o ecossistema Sentinel Vault! Para garantir a segurança, integridade arquitetural e governança do Core Engine, todas as interações devem seguir as diretrizes abaixo.

### 🤝 Como Você Pode Participar?
Como o Sentinel Vault opera sob uma licença proprietária de código visível, as contribuições não são de aceitação automática de código, mas sim focadas no enriquecimento intelectual do ecossistema:

* **Sugestões, Críticas e Diálogos Arquiteturais:** Encorajamos discussões profundas sobre melhorias de performance na JVM, novos padrões de criptografia ou técnicas avançadas de DevSecOps. Você pode abrir discussões e debater conceitos específicos através das ferramentas do repositório.
* **Relato de Bugs e Vulnerabilidades (Issues):** Caso encontre alguma falha de segurança (como desvios de autenticação ou brechas em endpoints do Actuator), abra uma Issue detalhando o cenário técnico, comportamento observado e o passo a passo para reprodução.
* **Pull Requests e Envio de Código:** Caso queira submeter uma melhoria de código, esteja ciente de que, ao enviar o Pull Request, você concorda em ceder os direitos de uso do código submetido para incorporação ao Core Engine principal, sem direito a reivindicações de propriedade intelectual sobre o produto final. O controle total e exclusivo permanece nas mãos do idealizador, Lucas Silva de Deus. Todo código enviado deve passar obrigatoriamente pela esteira automatizada de testes locais (`mvn test`).
